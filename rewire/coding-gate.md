# Coding gate

Deliberate personal rule. Never edited by the compiler — only by the user, directly.

- Before writing or editing any code file, lay out a short plan in plain text first — even when the user already asked for the feature or fix by name.
- Wait for an explicit go-ahead (`go ahead`, `yes`, `do it`, `proceed`, or similar) before making the edit.
- Once approved, further edits within that same approved task don't need a fresh go-ahead for every file — but a new user message that isn't itself an approval resets the gate for the next edit.
- Applies to Edit, Write, and NotebookEdit. Does not apply to read-only exploration, research, or running tests/commands to check current state.
